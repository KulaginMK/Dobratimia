Они лежат в `expo-app/.env.local`, и в репозиторий этот файл не попадает. Поэтому ни сервер сборки Expo, ни GitHub их не знают, и вписать их нужно в двух местах: шаг 1.3 (GitHub) и шаг 3.3 (EAS). ## Шаг 1. GitHub: репозиторий и веб-версия

GitHub Pages на бесплатном тарифе работает только у открытых репозиториев. Значит, код, `TODO.md`, макеты из `handoff/` и файлы базы будут видны всем. Паролей и ключей в истории репозитория нет, я проверил.

Новый репозиторий называется `KulaginMK/Dobratimia`, сайт будет на `https://kulaginmk.github.io/Dobratimia/` (решение от 10 октября 2026 года). Сейчас это имя занято старой веб-версией, поэтому сначала её нужно переименовать.

1. Переименовать старый репозиторий: https://github.com/KulaginMK/Dobratimia → **Settings** → **General** → **Repository name** → `Dobratimia-old` → **Rename**. Старый сайт переедет на `…/Dobratimia-old/`.
2. Создать новый: https://github.com/new → имя `Dobratimia`, **Public**, без README и без лицензии → **Create repository**.
3. Отправить код. Я подключаю репозиторий и отправляю ветку `main`, затем ветку этапа. Войти в GitHub из терминала нужно один раз, и обычный пароль там не подходит. Проще всего поставить программу `gh` и подтвердить вход в браузере:

```bash
brew install gh
```

```bash
gh auth login --web --git-protocol https
```

4. Переменные с адресом сервера: в репозитории **Settings** → **Secrets and variables** → **Actions** → вкладка **Variables** → **New repository variable**, два раза:
   - `EXPO_PUBLIC_SUPABASE_URL` — первая строка из `.env.local`, часть после знака `=`;
   - `EXPO_PUBLIC_SUPABASE_ANON_KEY` — вторая.
5. Включить сайт: **Settings** → **Pages** → **Build and deployment** → **Source**: **GitHub Actions**.

Сайт соберётся, когда этап 16 попадёт в ветку `main`. Сценарий деплоя лежит в ветке этапа, а GitHub запускает его только из основной ветки; кнопка **Run workflow** на вкладке **Actions** появится тогда же. Шаги 4 и 5 нужно сделать до переноса, иначе первая сборка сайта остановится с ошибкой про адрес сервера.

После переноса сайт откроется через три-четыре минуты по адресу `https://kulaginmk.github.io/Dobratimia/` и дальше будет обновляться сам при каждом переносе в `main`.

Как проверить: открывается первый шаг онбординга; прямая ссылка `https://kulaginmk.github.io/Dobratimia/sos` открывает SOS, а не страницу ошибки GitHub. Вход через Google заработает после шага 2.

Подпапку `/Dobratimia` сценарий берёт из имени репозитория. Если у сайта появится свой домен, в `.github/workflows/deploy.yml` переменную `WEB_BASE_URL` нужно будет сделать пустой.

## Шаг 3. EAS: сборка приложения

EAS — сервис Expo, который собирает приложение на своих серверах. На бесплатном тарифе сборки ждут в общей очереди, поэтому ждать приходится по-разному: от нескольких минут до часа и больше.

1. Аккаунт: https://expo.dev/signup. Карта не нужна.
2. Вход с компьютера. Я запущу команду в терминале приложения, вы введёте почту и пароль:

```bash
cd expo-app && npx eas-cli@latest login
```

3. Привязать проект и передать адрес сервера. Первая команда создаёт проект `dobratimia` в вашем аккаунте Expo и записывает его номер в `app.json`; если она попросит вписать номер вручную, я впишу. Вторая отправляет в EAS два значения из `.env.local`.

```bash
cd expo-app && npx eas-cli@latest init
```

```bash
cd expo-app && npx eas-cli@latest env:push production --path .env.local
```

4. Первая сборка, файл APK для телефона:

```bash
cd expo-app && npx eas-cli@latest build --platform android --profile preview --clear-cache
```

   Команда спросит **Generate a new Android Keystore?** — ответьте **Y**. Keystore — это ключ, которым подписано приложение. Он хранится в вашем аккаунте Expo, и без него нельзя выпустить обновление. Поэтому доступ к аккаунту Expo терять нельзя; позже я покажу, как скачать копию ключа.

   Когда сборка закончится, в терминале появятся ссылка и QR-код. Откройте ссылку на телефоне, скачайте файл и разрешите установку из браузера, когда Android об этом спросит.

5. Сборка для Google Play, файл AAB:

```bash
cd expo-app && npx eas-cli@latest build --platform android --profile production
```

   На странице сборки нажмите **Download** и сохраните файл `.aab`: он понадобится на шаге 5.

Ошибки собранного приложения в терминале не видны: оно не связано с компьютером, как Expo Go. Если что-то сломается без сообщения на экране, опишите, что нажимали. Обычные правки мы по-прежнему проверяем в Expo Go, там ошибки с телефона я вижу сам.

## Шаг 4. Google Play Console: аккаунт

Регистрация: https://play.google.com/console/signup. Беларусь есть в списке стран, где Google регистрирует разработчиков.

Первым делом Google спросит тип аккаунта, и от него зависит многое.

| | Личный | Организация |
|---|---|---|
| Что нужно | Документ, удостоверяющий личность | Зарегистрированная организация и её номер D-U-N-S |
| Доступ к открытой публикации | После закрытого теста: не меньше 12 тестировщиков 14 дней подряд (правило для личных аккаунтов, созданных после 13 ноября 2023 года) | Без такого теста |
| Приложения о здоровье | См. ниже | Разрешены |

В правилах Google сказано, что приложения о здоровье, «такие как медицинские приложения», публикуют только организации. В декларации о здоровье пункт «Психическое и поведенческое здоровье» (Mental and Behavioral Health) стоит в группе «Медицинские» (Medical). «Добратимия» с тестом DASS-21 и подбором психологов, по моему чтению, под него подпадает. Как Google применяет это правило к приложениям самопомощи, я в его справке не нашёл, поэтому этот вопрос стоит задать юристу до оплаты.

Для внутреннего тестирования подойдёт любой тип аккаунта. Если аккаунт уже есть, начинаем с ним.

Остальное при регистрации делаете вы: разовый взнос 25 долларов, проверка личности (может занять несколько дней), подтверждение телефона. У личного аккаунта Google может попросить подтвердить, что у вас есть Android-устройство, через мобильное приложение Play Console.

## Шаг 5. Внутреннее тестирование

Внутреннее тестирование — это до ста человек, которых вы добавляете по почте. Приложение не видно в поиске, проверка Google почти не задерживает выпуск.

Имя пакета `dobratimia.app` (решение от 13 октября 2026 года) после первой загрузки файла поменять нельзя.

1. **Создать приложение** (Create app): название «Добратимия», язык по умолчанию — русский, тип — приложение, бесплатное. Две галочки согласия внизу ставите вы.
2. Слева **Тестирование** → **Внутреннее тестирование** (Testing → Internal testing) → вкладка **Тестировщики** → **Создать список рассылки**: название любое, адреса Gmail участников → сохранить и отметить список галочкой.
3. Вкладка **Выпуски** → **Создать выпуск** (Create new release):
   - Google предложит подпись приложений Google Play (Play App Signing) — согласитесь;
   - загрузите файл `.aab` из шага 3;
   - в примечаниях к выпуску напишите: «Первая сборка для внутреннего тестирования»;
   - **Далее** → **Сохранить и опубликовать**.
4. На вкладке **Тестировщики** скопируйте ссылку для участия. Тестировщик открывает её на телефоне под своей почтой, принимает приглашение и ставит приложение из Google Play. У нового приложения ссылка может заработать не сразу, а через несколько часов.

Что сказать тестировщикам:

- Специалисты, их телефоны и служба ВГМУ вымышлены. Звонить по ним не нужно. Номера 133 и 103 настоящие.
- Часть текстов черновая: техники, «Анатомия», фразы «Доброго слова». Их ещё прочитает психолог.
- Войти смогут только те, чью почту вы добавили в Google Cloud → **Audience** → **Test users**.

Если на телефоне уже стоит APK из шага 3, перед установкой из Google Play его придётся удалить: у этих файлов разные подписи. Дневник и результаты тестов при удалении сотрутся.

### «Безопасность данных»: готовые ответы

Google считает «собранными» только те данные, которые уходят с телефона. Дневник настроения, ответы и результаты DASS-21, результаты КРИКа и текст «Выплеснуть текстом» остаются на устройстве, а звук с микрофона не записывается: приложение считает громкость в памяти. Поэтому категории «Здоровье и фитнес» (Health and fitness) и «Аудио» (Audio files) в форме не отмечаются.

Общие вопросы:

- Собирает ли приложение данные пользователей: да.
- Все ли данные шифруются при передаче: да, обмен с сервером идёт по HTTPS.
- Можно ли попросить удалить данные: да. В приложении это «Профиль» → «Удалить мои данные». Google просит ещё и веб-адрес, где можно удалить аккаунт без приложения; см. «Удаление аккаунта» ниже.
- Способ создания аккаунта: OAuth (вход через Google).
- Передаются ли данные третьим лицам: нет. Supabase хранит данные по нашему поручению, а по правилам формы это передачей не считается.

Какие данные отметить как собранные:

| Пункт формы | Что это у нас | Обязательно? | Цель |
|---|---|---|---|
| Personal info → Name (имя) | Имя из аккаунта Google | Да | Account management (управление аккаунтом) |
| Personal info → Email address (почта) | Почта аккаунта Google | Да | Account management |
| Personal info → User IDs (идентификаторы) | Номер аккаунта на сервере; имя в Telegram, если его указал специалист | Да | App functionality (функции приложения), Account management |
| Personal info → Phone number (телефон) | Телефон, который специалист сам указал в карточке | Нет | App functionality |
| Photos and videos → Photos (фото) | Фото карточки, если специалист его загрузил | Нет | App functionality |
| App activity → App interactions (действия в приложении) | Отметки «Нравится» специалистам, сердечки фразам, отметка «был сегодня», выбранный вуз | Да | App functionality, Analytics (аналитика) |
| App activity → Other user-generated content (другой контент пользователя) | Текст карточки специалиста: «О себе», цитата, образование | Нет | App functionality |

На вопрос «обрабатываются ли данные только временно» по каждой строке ответ «нет»: они хранятся на сервере.

Не отмечать: местоположение, финансы, сообщения, контакты, календарь, файлы, историю браузера, сведения о сбоях, идентификаторы устройства. Приложение этого не собирает, и сторонних счётчиков в нём нет.

### Декларация о здоровье

В форме отмечаются все функции, которые есть в приложении. По описаниям из справки Google к «Добратимии» подходят два пункта:

- группа «Здоровье и фитнес» → Stress Management, Relaxation, Mental Acuity (управление стрессом, релаксация): дыхание, техники, медитации;
- группа «Медицинские» → Mental and Behavioral Health (психическое и поведенческое здоровье): тест DASS-21 и подбор психологов.

Пункт Medical Device Apps (медицинское изделие) не отмечать: приложение им не является.

Второй пункт тянет за собой вопрос о типе аккаунта из шага 4. Окончательный выбор пунктов стоит сделать вместе с психологом и юристом.

Для приложений о здоровье, которые не являются медицинскими изделиями, Google требует, чтобы в описании прямо говорилось: приложение не медицинское изделие, не ставит диагнозов и не лечит, а по вопросам здоровья нужно обращаться к специалисту. В черновике описания ниже такой абзац есть.

### Удаление аккаунта

Google требует два пути: в самом приложении и по веб-адресу, чтобы человеку не пришлось ставить приложение заново. Первый есть. Вторым может стать веб-версия («Профиль» → «Удалить мои данные») вместе с абзацем в политике конфиденциальности, где это описано. Этот адрес вписывается в форму «Безопасность данных».

Вопрос юристу: когда специалист удаляет аккаунт, его карточка с именем, фото и контактами остаётся на сервере и только отвязывается от аккаунта. Убирает её администратор вручную. Нужно решить, удалять ли карточку автоматически.

**Название** (до 30 знаков): Добратимия

**Краткое описание** (до 80 знаков): Дневник настроения, дыхание, тест DASS-21 и психологи для студентов-медиков

**Полное описание:**

> «Добратимия» — бесплатное приложение самопомощи для студентов медицинских вузов Беларуси. В нём можно следить за своим состоянием, снять напряжение и найти психолога.
