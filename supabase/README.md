# Сервер «Добратимии»: как подключить Supabase и вход через Google

Пока эти шаги не сделаны, приложение работает как раньше — на заглушках, с входом-имитацией. Ничего не сломается, если отложить.

После подключения по-настоящему заработают: вход через Google, специалисты и их контакты с сервера, отметки «Нравится», сердечки фраз, счётчик «Сегодня вы не одни», удаление аккаунта.

Названия пунктов в панелях Supabase и Google время от времени меняются. Если чего-то не находите — пришлите скриншот, разберёмся.

## Что лежит в этой папке

| Файл | Что это | Когда нужен |
|---|---|---|
| `setup.sql` | Вся база одним файлом: таблицы, правила доступа, функции, список вузов | Шаг 2 |
| `demo.sql` | Вымышленные специалисты, фразы и служба ВГМУ из макетов — чтобы было что смотреть | Шаг 3 |
| `demo_remove.sql` | Удаляет вымышленные данные | Перед публикацией |
| `migrations/`, `seed.sql` | То же, что `setup.sql`, по частям — для разработки | Вам не нужны |

## Шаг 0. Три проверки до начала

Это решения, которые в спецификации оставлены за вами (`handoff/docs/08-data-and-backend.md`).

1. **Открывается ли Supabase из Беларуси.** Откройте https://supabase.com с домашнего интернета и с мобильного, без VPN. Если не открывается хотя бы где-то — остановитесь и напишите мне: студенты окажутся в том же положении, и тогда нужен другой сервис.
2. **Бесплатный тариф.** Платить не нужно, карта не нужна. Ограничение, о котором стоит знать: проект на бесплатном тарифе Supabase ставит на паузу, если к нему неделю никто не обращался. Пока идёт разработка, это может случиться; проект снимается с паузы кнопкой в панели.
3. **Юрист.** Покажите, что именно уходит на сервер (раздел «Что хранится на сервере» ниже) и где это хранится (регион из шага 1). Это нужно до публикации, а не до проверки.

## Шаг 1. Создать проект

1. https://supabase.com → **Start your project** → войдите (через GitHub или почту).
2. Если проектов у вас ещё не было, Supabase сначала попросит создать организацию: Name — любое, Plan — **Free**.
3. **New project**:
   - Name: `dobratimia`
   - Database Password: нажмите **Generate a password** и сохраните его у себя. Мне его присылать не нужно.
   - Region: **Central EU (Frankfurt)** — ближайший к Беларуси.
4. **Create new project** и подождите минуту-две.

## Шаг 2. Создать таблицы

1. В левом меню — **SQL Editor** → **New query**.
2. Откройте файл `supabase/setup.sql`, скопируйте всё его содержимое и вставьте в окно.
3. Нажмите **Run**. Supabase предупредит о «destructive operations» — так он реагирует на слово `delete` внутри функций; нажмите **Run query**. Должно появиться «Success. No rows returned».
4. Проверьте: **Table Editor** → в списке 11 таблиц, в таблице `universities` пять строк.

Запускать `setup.sql` нужно один раз. Если нажать второй раз, будет ошибка «already exists» — это не страшно, база уже создана.

## Шаг 3. Добавить вымышленные данные для проверки

Так же, как в шаге 2, вставьте в **SQL Editor** содержимое `supabase/demo.sql` и нажмите **Run**.

Появятся четыре специалиста из макетов, шесть фраз и «Психологическая служба ВГМУ». Это те же вымышленные люди и телефоны, что и в заглушках приложения. Перед публикацией их нужно удалить (`demo_remove.sql`).

## Шаг 4. Разрешить вход через Google — в Google Cloud

1. https://console.cloud.google.com → вверху выберите **New Project**, назовите `Dobratimia`, **Create**. Если вместо формы написано «Google Cloud access blocked», включите в Google-аккаунте двухэтапную проверку (кнопка **Enable MFA**) и через пару минут обновите страницу.
2. Меню → **APIs & Services** → **OAuth consent screen** (в новой панели это называется **Google Auth Platform**) → **Get started**:
   - App name: `Добратимия`
   - User support email: ваша почта
   - Audience: **External**
   - Contact information: ваша почта
3. Там же, раздел **Audience** → **Test users** → **Add users** → добавьте свою почту Gmail. Пока приложение в статусе «Testing», войти смогут только добавленные сюда люди.
4. Раздел **Clients** → **Create client**:
   - Application type: **Web application**
   - Name: `Supabase`
   - **Authorized redirect URIs** → **Add URI**. Адрес возьмите в Supabase: **Authentication** → **Sign In / Providers** → **Google** → поле **Callback URL (for OAuth)**. Он выглядит как `https://xxxxxxxx.supabase.co/auth/v1/callback`.
5. **Create**. Появятся **Client ID** и **Client secret** — они нужны на следующем шаге. Скопируйте их сразу: секрет Google показывает целиком только в этом окне.

## Шаг 5. Включить Google в Supabase

1. Supabase → **Authentication** → **Sign In / Providers** → **Google**.
2. Включите переключатель, вставьте **Client ID** и **Client Secret** из шага 4, **Save**.
3. **Authentication** → **URL Configuration**:
   - **Site URL**: `http://localhost:8081`
   - **Redirect URLs** → **Add URL**, по одному:
     - `http://localhost:8081/**`
     - `exp://**`
     - `dobratimia://**`

Первый адрес — для проверки в браузере, второй — для Expo Go на телефоне, третий — для будущей сборки приложения.

## Шаг 6. Сообщить приложению адрес сервера

Нужны два значения из Supabase:

- **Project URL** — **Project Settings** → **Data API**. Выглядит как `https://xxxxxxxx.supabase.co`.
- **anon public** ключ — **Project Settings** → **API Keys**. В новых проектах он может называться **Publishable key**.

Оба значения не секретные: они и так попадают в приложение, а данные защищают правила доступа в базе. Пришлите их мне в чат — я впишу сам. Секретный ключ (`service_role` / **Secret key**) и пароль базы присылать не нужно и нельзя никому показывать.

Если хотите вписать сами: в папке `expo-app` скопируйте файл `.env.example`, назовите копию `.env.local` и впишите значения после знаков `=`.

После этого сервер разработки нужно перезапустить: в терминале с ним нажмите `Ctrl+C` и запустите заново.

```bash
npm --prefix expo-app run phone
```

## Шаг 7. Проверить

1. В браузере: `http://localhost:8081` → «Войти через Google» → выберите аккаунт → вернётесь в приложение на выбор вуза или на Главную.
2. На телефоне в Expo Go — то же самое: откроется окно браузера с Google и закроется само. Запускать сервер нужно командой `npm --prefix expo-app run phone`: она подставляет в адрес сетевое имя компьютера (`….local`). Supabase не возвращает после входа на адрес с IP (`exp://192.168…`) — тогда вместо приложения откроется страница «localhost … could not be loaded».
3. Supabase → **Authentication** → **Users**: там появился ваш аккаунт. **Table Editor** → `profiles`: строка с вашим именем.
4. В приложении: «Специалисты» → «Нравится» → открылись контакты. В `likes` появилась строка.

## Как пользоваться панелью дальше

- **Сделать человека специалистом** (для кабинета, этап 13): **Table Editor** → `specialist_accounts` → **Insert row** → выберите карточку в `specialist_id` и впишите почту его Google-аккаунта. При следующем входе у него появится кабинет.
- **Проверить правки специалиста** (кабинет, этап 13). Когда специалист нажимает «Сохранить», его правки не попадают в карточку сразу, а ждут вас:
  1. **Table Editor** → `specialist_drafts`. Каждая строка — правки одного специалиста; в колонке `payload` — новые значения полей.
  2. Одобрить: **SQL Editor** → `select public.approve_draft('<specialist_id из этой строки>');` → **Run**. Правки перейдут в карточку и контакты, строка из `specialist_drafts` исчезнет, в кабинете появится «Опубликована и проверена администратором».
     Если вместо этого появилась ошибка со словами `check constraint`, в правках есть значение, которое база не принимает: ссылка на запись не с `https://`, больше пяти специализаций или цитата длиннее 140 знаков. Верните правки с замечанием.
     Если специалист заменил фото, в `payload` есть строка `photo_path`. Посмотреть фото до одобрения: **Storage** → `specialist-photos` → папка с id карточки → файл с этим именем.
  3. Вернуть с замечаниями: в строке черновика поставьте `status` = `changes_requested` и напишите замечание в `admin_comment`. Специалист увидит в кабинете «Есть замечания: …» и сможет поправить.
  4. Если специалист сменил имя или фамилию, после одобрения поправьте вручную `name_dative` в `specialists` («Ольге Мирошник») — приложение само склонять не умеет.
  5. Новая карточка видна студентам, только когда в `specialists` в колонке `published` стоит `true`.
- **Сколько сердечек у каждой фразы**: **Table Editor** → `phrase_like_stats`. Приложению и пользователям этот список недоступен — только вам.
- **Добавить или поправить фразу, вуз, сотрудника службы**: соответствующая таблица в **Table Editor**.
- **Контакты специалиста** лежат в `specialist_contacts`. Студент видит их только после «Нравится» и только если в колонке `consent` стоит `true`.

## Перед публикацией

- [ ] Удалить вымышленные данные: `demo_remove.sql`.
- [ ] Убрать `exp://**` из **Redirect URLs** — это адрес Expo Go, в готовом приложении он не нужен.
- [ ] Заменить **Site URL** на адрес веб-версии и добавить его в **Redirect URLs**.
- [ ] Google Cloud → **Audience** → **Publish app**, чтобы войти мог любой, а не только тестовые пользователи.
- [ ] Показать юристу схему данных и регион хранения.

## Что хранится на сервере

| Что | Зачем |
|---|---|
| Имя и почта Google-аккаунта | Вход |
| Выбранный вуз | Чтобы не выбирать заново на новом телефоне |
| Отметки «Нравится» специалистам | Открывают контакты; специалист видит только их число |
| Сердечки фразам «Доброго слова» | Команда видит число сердечек у каждой фразы |
| Факт «был сегодня» | Счётчик на Главной; строки старше двух дней удаляются |
| Карточка специалиста и его контакты | Их заполняет сам специалист в кабинете; студентам видна только одобренная версия |
| Фото специалиста, если он его загрузил | Показывается на карточке. Лежит в открытом хранилище `specialist-photos`: открывается по прямой ссылке без входа |

Чего на сервере нет и быть не должно: дневник настроения, ответы и результаты DASS-21, результаты КРИКа, текст «Выплеснуть текстом», голос. Для них в базе нет таблиц.

Администратор в панели Supabase видит все строки, в том числе кто кому поставил «Нравится»: правила доступа действуют для приложения, а не для владельца базы. Поэтому на экране статистики кабинета написано «…не видно ни вам, ни другим пользователям», а не «…ни администратору»; это же нужно учесть в политике конфиденциальности.

## Проверка правил доступа

Правила проверяются тестами, для них не нужен ни интернет, ни проект Supabase:

```bash
npm --prefix expo-app run test:db
```

Главный из них — «контакты специалиста без отметки «Нравится» не читаются».
