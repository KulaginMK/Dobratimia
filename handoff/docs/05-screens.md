# 05. Экраны

Эталон каждого экрана — два файла с одинаковым именем:

- `reference/screens-png/<Имя>.png` — как выглядит (412×915 dp, отрисовано в 2×);
- `reference/screens-html/<Имя>.dc.html` — разметка: точные тексты, отступы, размеры, цвета через токены (`var(--color\.primary)` = `t.color.primary`). Теги `<x-import component-from-global-scope="Dobratimia.Button" …>` — это компоненты UI-кита с теми же пропсами в kebab-case. `{{…}}` и `<sc-for>` — данные и списки (их значения в `<script>` внизу файла).

Несколько html-файлов — это **состояния одного экрана**, а не отдельные маршруты (например, `Scream`, `ScreamLive`, `ScreamResult`).

HTML-файлы — для чтения, а не для запуска: им нужен рантайм холста дизайна, которого в пакете нет. Как выглядит экран — смотрите PNG; веб-эталон компонентов — `design-system/web-reference/`.

Если docs расходятся с html — прав docs (в них учтены исправления после макетов: SOS на всех экранах, сегменты 48, тексты DASS-21 и т. п.).

## Экраны по группам

### 1. Онбординг (показывается один раз; флаг в AsyncStorage)

| Эталон | Что на экране | Действия |
|---|---|---|
| Main | Тимка `hello`, «Здесь можно выдохнуть», 3 пункта, прогресс 1/5, «Пропустить» | Дальше → warning; Пропустить → sign-in |

| OnbSignIn | Логотип, «Войдите, чтобы начать», кнопка Google, ссылки на политику и согласие | Google → university (или сразу в приложение, если вуз уже выбран) |

- **Сразу после «Нравится»** — как на эталоне, с плашкой; «Назад» ведёт к подбору (подпись «Назад к подбору»).
