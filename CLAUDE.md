# Добратимия — инструкции для Claude Code

Бесплатное приложение самопомощи для студентов медицинских вузов Беларуси: отследить состояние, снять напряжение, найти психолога. Android (Google Play) и веб из одного кода. Интерфейс только на русском.

Владелец проекта не пишет код сам — весь код пишешь ты. Поэтому: объясняй решения простыми словами, делай маленькие проверяемые шаги, после каждого шага говори, как проверить результат на телефоне или в браузере.

## Где что лежит

```
CLAUDE.md                  этот файл
handoff/                   пакет передачи дизайна (только читать; исключения — в «Как работать»)
  docs/                    спецификации — читай перед каждой задачей нужный файл
  reference/screens-png/   скриншоты всех 39 экранов 412×915 — эталон внешнего вида
  reference/screens-html/  разметка тех же экранов: точные тексты, отступы, размеры
  design-system/           tokens.json, брендбук, веб-эталон компонентов (bundle.js/.css, index.d.ts)
  src/                     готовый код: тема и бренд-компоненты (скопировать в приложение)
  assets/                  SVG логотипа, Тимки, иконок; PNG иконки приложения и сплэша
expo-app/                  приложение (создаётся на шаге 0, см. docs/11-roadmap.md)
web/                       старая веб-версия на Vite — не трогать, не переносить из неё код
```

## Стек

- Expo SDK 57 (React Native 0.86, React 19.2), TypeScript `strict`, новая архитектура.
- Навигация: `expo-router` (файловые маршруты). Жесты и анимации: `react-native-gesture-handler` + `react-native-reanimated`.
- Графика: `react-native-svg`. Шрифты: `expo-font` + `@expo-google-fonts/nunito`, `@expo-google-fonts/golos-text`.
- Зависимости ставь через `npx expo install <пакет>` — так версии совпадут с SDK.
- Новые нативные библиотеки добавляй только если без них нельзя; сначала проверь, есть ли модуль Expo.

## Жёсткие правила

1. **Дизайн — из пакета.** Цвета, отступы, радиусы, шрифты — только через `useTheme()` (`theme.color.primary`, `theme.space.md`, `theme.type.h1`). Никаких hex-кодов в коде вне `src/theme`. В экранах — без «магических» чисел. Внутри компонентов UI-кита (`src/components`) допустимы точные размеры из веб-эталона `bundle.css` и docs/04 (например, заголовок шторки 20/26, радиус крупной кнопки 20) — оформляй их константами в начале файла. Если нужного значения нет ни в токенах, ни в эталоне — спроси, не придумывай.
2. **Сверяйся со скриншотом.** Перед версткой экрана открой `handoff/reference/screens-png/<Экран>.png` и `screens-html/<Экран>.dc.html`. Тексты копируй дословно из html. Исключения: демонстрационные данные (имена, телефоны, цифры — docs/10) и текст утверждения на DassQuestion — он условный, утверждения DASS-21 берутся только из валидированной версии (docs/07). Где docs расходятся с html, прав docs: там учтены исправления после макетов.
3. **SOS виден всегда.** На каждом экране, кроме онбординга, самого SOS и кабинета специалиста, в шапке есть кнопка SOS (см. docs/06-navigation.md). На Медитациях, Pomodoro и Избранных её нет в макетах — добавь круглую `SosRound`. Не прячь её в меню.
4. **Никаких диагнозов и медицинских обещаний.** «Высокий уровень тревоги по шкале DASS-21», а не «у вас тревожное расстройство». «Может помочь», а не «вылечит». Тон: на «вы», тепло, без канцелярита и эмодзи (docs/02-brand.md).
5. **Чувствительные данные — только на устройстве.** Ответы DASS-21, дневник настроения, результаты и текст КРИКа не отправляются на сервер (docs/08-data-and-backend.md). Голос не записывается и не сохраняется: только уровень громкости.
6. **Доступность.** Область касания ≥ 48 dp. У каждой кнопки-иконки есть `accessibilityLabel`. Цвет не единственный носитель смысла. Учитывай «Уменьшить движение» (`useReducedMotion` из Reanimated). Подробно — docs/09-accessibility.md.
7. **Две темы.** Светлая основная, тёмная обязательна. Проверяй каждый экран в обеих.
8. **Заглушки помечай.** Всё вымышленное (имена специалистов, телефоны вузов, счётчики) — в `src/data/mocks/` с комментарием `// ЗАГЛУШКА`. Полный список — docs/10-placeholders.md. Не выдумывай новые телефоны и адреса.
9. **Веб тоже работает.** Каждая фича проверяется в `npx expo start --web`. Где поведение отличается (микрофон, уведомления, карта) — описано в docs/07-features.md.

## Как работать

- Порядок задач — docs/11-roadmap.md. Не перескакивай этапы: сначала каркас и UI-кит, потом экраны, потом бэкенд.
- Одна задача — один коммит с понятным сообщением на русском.
- После изменения запусти `npx tsc --noEmit` и `npx expo lint`. Ошибки не оставляй.
- Если в спецификации противоречие или пробел — остановись и задай владельцу один конкретный вопрос с вариантами.
- Не удаляй и не переписывай файлы в `handoff/`. Тема и бренд-компоненты копируются из `handoff/src/` в `expo-app/src/` один раз, дальше правятся там. Исключения — источники правды, которые меняются только по решению владельца: `handoff/design-system/tokens.json` (токены) и `handoff/assets/svg/` (иконки, логотип, Тимка); после правки перегенерируй код скриптами из `handoff/tools/`.
